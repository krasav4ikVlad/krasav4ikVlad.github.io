# Структура проекта и правила, по которым она держится

Скелет собран под конкретную боль текущего бота: `start.py` — 3100 строк с
одним хендлером на 40 `if`, `utils.py` — 3400 строк, где рядом лежат HTTP к
панели, расчёт цен, рендер экранов и крон биллинга, три файла кампаний по
600 строк с одинаковыми `safe_send` / `_is_good_hour` / `_notify_admin`.

Разбиение сделано так, чтобы **каждая вещь имела ровно одно место**.

## Семь правил, которые держат структуру

**1. Направление зависимостей — только вниз.**

```
handlers → services → repositories → Mongo
              ↓
           domain (не зависит ни от чего)
```

Хендлер не ходит в Mongo. Сервис не знает про `CallbackQuery`. `domain/`
не импортирует ни aiogram, ни motor — поэтому цены проверяются тестом за
миллисекунды.

**2. Никаких глобальных импортов состояния.** `from loader import users, bot`
— причина, по которой сейчас нельзя ни протестировать, ни запустить кусок
кода отдельно. Всё приезжает через `Container`: боту — middleware, API —
`app.state.container`, тестам — заглушки.

**3. Настройки против конфига.** Секрет или адрес — в `.env` (`core/config.py`).
Цена, процент, тумблер — в `settings/schema.py` и меняется из админки без
деплоя. Если сомневаетесь: «захочу ли я поменять это в час ночи с телефона?»
Да — значит, настройка.

**4. Текст живёт в реестре, не в коде.** В хендлере — ключ
(`texts.render('screen.subscription.empty')`). Иначе одна формулировка
расползается по пяти местам, как сейчас блок «Профиль / Баланс / Друзей».

**5. Повторяющееся поведение — движок + таблица.** Кампании, админка,
платёжки построены одинаково: один универсальный исполнитель и данные к
нему. Новое касание рассылки, новая настройка, новая платёжка — это строка
или маленький класс, а не копия 200 строк.

**6. Деньги — только через атомарные операции.** `users.charge()` содержит
`'info.balance': {'$gte': amount}` внутри самого запроса, `claim_campaign_slot()`
ставит флаг и начисляет бонус одним `update_one`. Это то, что закрывает
двойное списание при двойном клике и повторный бонус при перезапуске
планировщика.

**7. Каждый файл отвечает на один вопрос.** Ориентир: модуль > 300 строк —
повод разрезать. Хендлер > 50 строк — логика утекла в UI-слой.

## Что уже работает в скелете

`pytest -q` → **554 passed**. Тесты идут на заглушках Mongo и Telegram
(`tests/conftest.py`), включая сценарии, которые иначе проверяются только на
живых пользователях:

| Тест | Что доказывает |
|---|---|
| `test_users_repo.py::test_double_click_cannot_go_negative` | второе нажатие «Купить» не уводит баланс в минус |
| `test_campaigns.py::test_blocked_user_does_not_get_bonus_twice` | заблокировавший бота получает бонус один раз |
| `test_campaigns.py::test_sends_only_inside_window` | окна отправки и ночная пауза |
| `test_renewal.py::test_money_is_taken_before_the_panel` | панель упала — деньги вернулись |
| `test_device_billing.py::test_charge_moves_the_right_package` | списание сдвигает дату своему пакету, а не соседнему |
| `test_bot_flow.py::test_buying_plan_charges_and_creates_subscription` | покупка через настоящий Dispatcher |
| `test_gifts.py::test_link_works_only_once` | подарочная ссылка не активируется дважды |
| `test_settings.py::test_percent_input_and_output` | 20 на вводе → 0.2 в базе → «20%» на экране |
| `test_admin_panel.py` (5 шт.) | админка целиком через реальный `Dispatcher` |

Три ошибки нашлись прямо при написании этих тестов: точки в ключах настроек
Mongo превращал во вложенные документы; обмен порядка элементов вырождался
в присваивание; роутер-синглтон нельзя подключить к двум диспетчерам.

## Порядок переноса

Писать с нуля всё сразу не нужно — бот должен зарабатывать всё это время.

1. ✅ **Каркас.** `core/`, `settings/`, `repositories/`, `admin/`. Имена
   переменных окружения и коллекций совпадают с текущими, миграция `m0003`
   переносит коллекции с пробелом в имени.
2. ✅ **Деньги.** `services/topup.py` + `api/webhooks.py`: шесть эндпоинтов
   схлопнуты в один, зачисление — единственный путь.
3. ✅ **Напоминания.** `services/expiry.py` + `api/remnawave.py`: приходят
   вебхуками панели вместо обхода базы раз в 15 минут.
4. ✅ **Панель.** `integrations/vpn/remnawave.py` + `services/squads.py` +
   `services/lifeline.py`: все HTTP-вызовы и раскладка сквадов в одном месте.
5. ✅ **Экраны.** Разделы разнесены по файлам `bot/handlers/*`, каждый — роутер
   через `create_router()`. Логики в них нет: только сборка экрана и вызов
   сервиса.
6. ⬜ **Кампании.** Тексты — в `content/texts.py`, касания — в
   `campaigns/definitions.py`, старые три файла удаляются целиком.
7. ✅ **Биллинг-крон.** `utils.process_subscriptions` (≈290 строк) разделён на
   `services/renewal.py` (автопродление) и `services/devices.py` (плата за
   доп. устройства); напоминания оттуда ушли в вебхуки.
8. ✅ **Остальные сервисы.** `promo.py`, `gifts.py`, `payouts.py`, `survey.py`
   — вся логика вокруг подписки перенесена и покрыта тестами.
9. ⬜ **Миграция данных.** `m0002_transactions_format` приводит транзакции к
   одному формату, после чего исчезают все разборы «список или словарь».

## Что осталось заполнить

Файлы со `raise NotImplementedError` — это точки переноса старого кода, а не
забытые куски: `integrations/vpn/remnawave.py`, `scheduler/jobs.py`,
экран `my_subscription` и разделы-заглушки в `bot/handlers/`. В каждом стоит
комментарий, откуда именно переносить.
