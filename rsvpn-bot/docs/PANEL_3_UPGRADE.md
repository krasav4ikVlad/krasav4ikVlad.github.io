# Обновление Remnawave до 3.x

Порядок один и он важен: **сначала бот, потом панель**. Наоборот — и между
двумя обновлениями бот не сможет ни выдать подписку, ни продлить её.

## Почему бота нужно обновить первым

С версии 3.0 панель опознаёт пользователя числовым `id`, а поле `uuid` из
ответов убрано совсем. У бота в базе на каждого человека лежит именно uuid,
и панель 3.x его не понимает: отказ на продление, на лимит устройств, на
блокировку, на статистику — на всё.

Сборка 109 и новее говорит с обеими версиями одновременно и по виду
значения понимает, с какой именно. Это не запас прочности: в день
обновления у старых подписок в базе ещё uuid, у новых уже id, и
перемешанная база — нормальное состояние.

Что ещё поправлено в боте под 3.x:

* тело `PATCH /api/users` называет пользователя `id` или `uuid` по виду
  ссылки — лишнее поле 3.x отвергает проверкой схемы, а не игнорирует;
* приняты новые коды ответов: `201` на создание, `202` и `204` без тела.
  Раньше успешное удаление читалось как отказ;
* отвязка устройства называет пользователя `userId` или `userUuid`;
* расход по скваду раскладывается и по `username`: что означает `id` в
  статистике, у версий своё, а username остаётся telegram id при любой;
* сам расход спрашивается по двум адресам — в 3.x ручка переехала из
  `bandwidth-stats` к самим сквадам, но у части сборок старый путь ещё
  отвечает. Перебор идёт от нового к старому и запоминается;
* ссылки подключения больше не перепроверяются по telegram id, когда
  ссылка уже числовая. Путь ждёт `userId` панели, а telegram id тоже
  число — на 3.x такой запасной вариант в теории попадал бы в чужую
  подписку.

Что бот **не** использует и потому переезда не требует: `/api/ip-control`
(переименован в `/api/connections`), поиск по telegram id, email и тегу,
bulk-операции, `/api/keygen`, `/api/subscription-settings`,
`responseHeaders` внешних сквадов, `/api/users/resolve`, `/api/metadata`.
Изменения в них на бота не влияют.

## Шаг 1. Обновить бота

```bash
cd /home/rsvpn-bot && ./scripts/update.sh
```

Скрипт включает режим техработ, забирает новую версию, ставит зависимости,
перезапускает процессы и выключает режим. На старой панели он отработает
как обычное обновление — шаг с переездом идентификаторов сам поймёт, что
переезжать некуда.

После этого убедитесь, что бот работает как раньше: купите подписку
тестовым аккаунтом, откройте `/diag`.

## Шаг 2. Подготовить `.env` панели

Это делается руками в `/opt/remnawave/.env`:

1. **Переименовать** `JWT_AUTH_SECRET` → `APP_SECRET`. Значение то же.
2. **Удалить** `JWT_API_TOKENS_SECRET`, `SWAGGER_PATH`, `SCALAR_PATH`,
   `IS_DOCS_ENABLED`.

Пути к документации теперь постоянные: `/api/backend-tools/swagger`,
`/api/backend-tools/scalar`, `/api/backend-tools/queues`.

## Шаг 3. Сжатие ответов на прокси

Панель 3.x больше не сжимает ответы сама. Без этого подписки поедут
тяжело — включите сжатие на обратном прокси:

* **Caddy** — директива `encode`;
* **Nginx** — `gzip on` и `gzip_types`.

## Шаг 4. Бэкап и обновление панели

Полный бэкап базы и `.env` — обязателен.

```bash
cd /opt/remnawave && nano docker-compose.yml     # image: remnawave/backend:3
cd /opt/remnawave && docker compose pull remnawave \
  && docker compose down && docker compose up -d && docker compose logs -f
```

Миграции базы панель выполняет сама при старте.

Про ноды: нода 3.3+ требует панель 3.3+, а панель 3.3 работает с нодами
3.2.3 и старше. Поэтому панель обновляется первой.

## Шаг 5. Перевести подписки на числовые id

```bash
cd /home/rsvpn-bot && .venv/bin/python -m scripts.panel_ids fix
```

То же делает команда `/panelids fix` в боте и фоновая задача раз в час —
так что если забыть, всё переедет само в течение часа.

Обратного поиска по uuid в 3.x нет, поэтому каждого человека бот
спрашивает заново по `shortUuid`: эта ручка не менялась, а сам shortUuid
считается от telegram id и есть даже у подписок из старого бота, где его
не сохраняли.

## Шаг 6. Проверить

* `/panelids` — должен ответить «все подписки опознаются панелью»;
* `/errors` — здесь виден настоящий ответ панели, если что-то не так;
* `/diag` — фоновые задачи и вебхуки;
* купить и продлить подписку тестовым аккаунтом, открыть менеджер
  устройств.

## Если придётся откатиться

Откат панели на `:2` возвращает uuid, а у переведённых подписок в базе бота
лежат числа. Это чинится тем же способом, что и переезд туда:

```bash
cd /home/rsvpn-bot && .venv/bin/python -m scripts.panel_ids fix
```

Направление бот выбирает не по своему намерению, а по тому, чем панель
называет пользователя сейчас: увидит uuid — переведёт ссылки обратно на
uuid. Фоновая задача сделает это сама в течение часа.

Восстанавливать базу бота из бэкапа для этого не нужно.
