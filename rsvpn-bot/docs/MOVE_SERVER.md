# Переезд бота на другой сервер

Повод, по которому это написано: сервер бота забанили в РФ, а база лежит
в РФ — и бот перестал до неё доставать. Машина сменилась, база осталась
на месте.

Порядок выбран так, чтобы **в каждый момент был откат**, а два главных
риска не сработали:

* **два бота с одним токеном.** Telegram отдаёт обновления по очереди то
  одному, то другому: половина нажатий пропадает, и выглядит это как
  «бот работает через раз». Поэтому старый бот останавливается **до**
  запуска нового, а не после;
* **вебхуки платёжек.** Они приходят на домен, а домен смотрит на старый
  IP. Пока DNS не переехал, оплаты не зачисляются — деньги у людей
  списались, а баланс не пополнился. Это чинится, но лучше не чинить.

База при этом не трогается вовсе: она на отдельной машине, и переезд
бота её не касается.

---

## 0. Проверить новый сервер ДО всего остального

Пять минут здесь стоят дешевле, чем переезд на машину, с которой всё
повторится.

```bash
# добивает ли новый сервер до базы — то, из-за чего всё и затевалось
nc -vz 195.133.30.98 27017

# и до Telegram
curl -s https://api.telegram.org | head -c 100

# и до панели
curl -sI https://ПАНЕЛЬ/api/ | head -1
```

Порт 27017 закрыт — дело не в бане, а в фаерволе базы: на машине с Mongo
нужно разрешить новый IP (`bindIp` в `/etc/mongod.conf` и правило в
фаерволе), иначе новый сервер будет так же молчать.

Питон: нужен 3.11 или новее (`python3 -V`).

## 1. На старом сервере: собрать то, чего нет в git

```bash
cd /home/rsvpn-bot
./scripts/backup.sh
```

Соберёт `.env`, свои эмодзи, картинки экранов и энкодер INCY в один архив
в домашнем каталоге. Именно этот список забывают: код-то переедет через
`git clone`, а бот поднимется без картинок, со стандартными значками и
без платёжных ключей.

Заодно, раз уж руки в терминале:

```bash
mongodump --uri="$TOKEN_DB" --db RS_2 --out ~/backup-$(date +%F)
```

Снимок базы к переезду отношения не имеет, но стоит пять минут.

## 2. На новом сервере: код и окружение

```bash
apt update && apt install -y python3-venv git nodejs npm
npm install -g pm2

cd /home
git clone -b claude/telegram-bot-refactor-admin-mmapc3 \
  https://github.com/krasav4ikVlad/krasav4ikVlad.github.io.git rsvpn-src
ln -s /home/rsvpn-src/rsvpn-bot /home/rsvpn-bot
cd /home/rsvpn-bot

python3 -m venv .venv
.venv/bin/pip install -U pip
.venv/bin/pip install -r requirements.txt
mkdir -p logs
```

**Не переносите подкаталог наружу** (`mv rsvpn-src/rsvpn-bot /home/`):
вместе с ним не уедет `.git`, лежащий уровнем выше, и `git pull` работать
не будет — обновления станут молча не доходить.

## 3. Перенести настройки

```bash
# с нового сервера
scp root@СТАРЫЙ_IP:~/rsvpn-move-*.tar.gz .
tar -xzf rsvpn-move-*.tar.gz -C /home/rsvpn-bot
```

Если в архиве был `incy_encode.mjs.backup` — положите его туда, куда
смотрит `INCY_ENCODER` в `.env`, и поправьте путь, если он другой.

Проверка, что всё на месте:

```bash
cd /home/rsvpn-bot
.venv/bin/python -m scripts.check_setup
```

Должно быть зелено по конфигу, базе и панели. Красное на базе — вернитесь
к шагу 0, дальше идти незачем.

## 4. Остановить старого бота

Вот здесь начинается простой, и он длится до конца шага 5. Обычно это
меньше минуты.

```bash
# на СТАРОМ сервере
pm2 stop rsvpn-bot rsvpn-api
pm2 save
```

Не `delete` — остановленный процесс это и есть кнопка отката.

Telegram копит сообщения, пока бот молчит, и отдаст их новому боту сразу
после старта. Ничего не потеряется.

## 5. Запустить нового

```bash
# на НОВОМ сервере
cd /home/rsvpn-bot
pm2 start ecosystem.config.js
pm2 save
pm2 startup          # чтобы поднялся сам после перезагрузки
```

Проверить:

```bash
./scripts/why.sh
```

Всё зелёное и «Токен занят другим процессом» **не** появилось — переезд
состоялся. Появилось — где-то остался старый процесс, ищите его на старой
машине.

Напишите боту `/start` и `/diag`.

## 6. Вебхуки: домен на новый IP

До этого шага оплаты не зачисляются: деньги у человека списались, а
уведомление ушло на старый сервер, где бот уже не слушает.

1. В панели DNS смените A-запись `webhook.rsvps.tech` на новый IP (TTL
   обычно 5–60 минут);
2. на новом сервере поднимите nginx и сертификат:

```bash
apt install -y nginx certbot python3-certbot-nginx
certbot --nginx -d webhook.rsvps.tech
```

   nginx должен проксировать на порт из `API_PORT` в `.env`;
3. проверьте снаружи: `curl -sI https://webhook.rsvps.tech/health`;
4. в панели Remnawave поправьте адрес вебхука, если он вбит руками.

Настройку `pay.callback_base` в `/admin → Платёжные методы` менять не
нужно, если домен остался прежним. Сменили домен — поправьте и её.

**Пока DNS не переехал**, платежи копятся неподтверждёнными. Что с ними
делать — `/outage`: он покажет оплаты, которые не зачислились, поимённо.

## 7. Через сутки

```bash
# на старом сервере, когда всё точно работает
pm2 delete rsvpn-bot rsvpn-api
rm -f ~/rsvpn-move-*.tar.gz     # в нём ключи платёжек
```

И на новом тоже удалите распакованный архив.

---

## Если что-то пошло не так

Откат занимает столько же, сколько переезд:

```bash
# на новом
pm2 stop rsvpn-bot rsvpn-api
# на старом
pm2 start rsvpn-bot rsvpn-api
```

DNS вернуть обратно, если успели сменить.

## Что переехало и что нет

| | переезжает | как |
|---|---|---|
| Код | да | `git clone` |
| `.env`, эмодзи, картинки, INCY | да | `scripts/backup.sh` |
| Настройки из админки | **не нужно** | лежат в базе |
| Тарифы, промокоды, пользователи | **не нужно** | лежат в базе |
| Сама база | нет | отдельная машина |
| Домен вебхуков | руками | шаг 6 |
| Сертификат TLS | заново | `certbot` на новом |
