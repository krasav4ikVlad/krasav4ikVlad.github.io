# Копии базы

Бот каждую ночь в 00:00 снимает копию всей базы, кладёт её на диск
сервера и присылает файл в личку админам. Ничего настраивать на сервере
не нужно: ни крона, ни `mongodump` — задача живёт внутри бота.

Пока идёт снимок, бот продолжает работать: сжатие и проверка вынесены в
отдельный поток, цикл событий в это время свободен и отвечает людям.

## Где лежат

По умолчанию `~/rsvpn-backups` (то есть `/root/rsvpn-backups`, если бот
запущен от root). Каталог нарочно вне папки бота — обновление `./scripts/update.sh`
делает `git pull`, и копиям там не место.

Имя файла: `RS_2-2026-09-30-0412.jsonl.gz` — база, дата, время.

## Что внутри

Построчный JSON с сохранением типов Mongo (даты остаются датами,
`ObjectId` — `ObjectId`), сжатый gzip. Одна строка — один документ:

```json
{"c": "users", "d": {"_id": {"$oid": "..."}, "user_data": {...}}}
```

Каждый снимок сразу после записи прочитывается обратно и сверяется по
числу документов. Если не сошлось — файл удаляется, а в админ-чат уходит
сообщение, что копия **не** сделана. Архив, который не открывается, хуже
отсутствия архива: на него рассчитывают.

## Команды

| Команда | Что делает |
|---|---|
| `/backup` | снять копию сейчас и прислать файл в чат (если он меньше 50 МБ) |
| `/backups` | какие копии есть, когда делались, сколько весят |

В `/backups` видно и то, что копия давно не делалась, — если последняя
старше двойного срока, об этом сказано прямо там.

## Настройки

Админка → Настройки → **Резервные копии базы**:

* **Делать копии базы** — выключатель;
* **Во сколько делать** — час по времени бота, по умолчанию 0 (полночь);
* **Сколько хранить** — 14 штук, старые удаляются сами;
* **Каталог для копий** — пусто означает `~/rsvpn-backups`;
* **Присылать файл в личку админам** — включено. Адресаты — только те
  id, что стоят в `.env`: в снимке вся база, почты, платежи и переписка
  с поддержкой;
* **Не слать файлы больше** — 45 МБ на один файл. Telegram не принимает
  документы больше 50, поэтому снимок крупнее режется на части.

Срок считается от назначенного часа, а не от времени последнего запуска:
перезапустили бота днём — расписание не сдвинулось. Пропущенная из-за
простоя полночь не теряется: снимок сделается при первой возможности,
иначе сутки остались бы без копии и никто бы не узнал.

## Если файл пришёл частями

Большой снимок приходит несколькими файлами `…jsonl.gz.001`, `.002` и так
далее; к последнему приложена команда сборки. Сложить обратно:

```bash
cat RS_2-2026-09-30-0000.jsonl.gz.* > RS_2-2026-09-30-0000.jsonl.gz
```

Порядок задаётся именами, так что `*` разложит их правильно. Дальше это
обычный снимок — восстанавливается как описано ниже.

## Восстановление

Отдельным скриптом и нарочно не кнопкой: восстановление базы нажатием с
телефона — это способ однажды потерять вечер.

Сначала посмотреть, что внутри (базу не трогает):

```bash
cd /home/rsvpn-bot
.venv/bin/python -m scripts.dbrestore ~/rsvpn-backups/RS_2-2026-09-30-0412.jsonl.gz
```

Залить в тестовую базу и проверить на ней:

```bash
.venv/bin/python -m scripts.dbrestore ~/rsvpn-backups/файл.jsonl.gz --into RS_2_test --yes
```

Залить в боевую:

```bash
pm2 stop rsvpn-bot rsvpn-api
.venv/bin/python -m scripts.dbrestore ~/rsvpn-backups/файл.jsonl.gz --yes --drop
pm2 start rsvpn-bot rsvpn-api
```

Скрипт спросит имя базы для подтверждения — это последняя проверка того,
что команда набрана в том окне.

`--drop` очищает коллекции перед заливкой, то есть возвращает базу ровно
к состоянию снимка. Без него документы из снимка перезапишут текущие по
`_id`, а всё, чего в снимке нет, останется на месте — так восстанавливают
случайно удалённое, не теряя того, что появилось позже.

## Чего копии не заменяют

Копия лежит на том же сервере, что и бот. Если сервер пропадёт целиком —
пропадёт и она. Раз в неделю имеет смысл забирать свежий файл к себе:

```bash
scp root@сервер:/root/rsvpn-backups/$(ssh root@сервер 'ls -t /root/rsvpn-backups | head -1') .
```

Или просто сохранять файл, который бот присылает по `/backup`.
