# Откуда панель оператора берёт данные

Что бот пишет и где это лежит. Документ для того, кто делает
`operator.nodewiki.info`: под каждый блок панели — коллекция, поля и
подводные камни.

База одна на всё, отдельного API у бота нет: панель читает Mongo напрямую.
**Читает**, а не пишет: деньги двигает только бот, иначе баланс и журнал
разъедутся.

---

## 1. Карточка пользователя

**Коллекция `users`**, поиск по `user_data.user_id` (число) или
`user_data.username` (без «@»).

| Поле панели | Путь в документе |
|---|---|
| Баланс | `info.balance` |
| Реферальный баланс | `info.ref_stats.withdrawable` |
| Тариф | `vpn.period` — число дней; название ищите в `plans` по `days` |
| Лимит устройств | `vpn.hwidDeviceLimit` |
| Подписка до | `vpn.expireAt` |
| Токен подписки | `vpn.shortUuid` |
| UUID в панели | `vpn.uuid` |
| ByPass: трафик | `vpn.bypass_trafficLimitBytes` (байты) |
| ByPass: до | `vpn.bypass_expireAt` |
| ByPass: лимит устройств | `vpn.bypass_hwidDeviceLimit` |
| Email | `info.email` |
| Сегмент | `growth.segment` |
| Заблокирован | `info.is_banned` |
| Бот заблокирован юзером | `growth.blocked_bot` |

**Даты бывают строками** — наследство старого бота. Парсите оба варианта:
ISO-строку и `Date`.

## 2. Движение денег — главный блок

**Коллекция `balance_log`.** Пишется с версии 104; всё, что было до неё,
лежит в `logs_balance` (старый бот) и `info.transactions` (см. ниже).

```jsonc
{
  "user_id": 802421217,
  "at": ISODate("2026-08-30T15:04:00Z"),
  "amount": -75,              // ЗНАКОВАЯ: + приход, − расход
  "direction": "out",         // in | out — то же самое словом
  "account": "balance",       // balance | referral — на каком счёте
  "kind": "devices",          // машинный код операции
  "title": "Доп. устройства", // человеческое название kind
  "description": "Доп. устройства: 1 шт.",
  "source": "user",           // user | auto | admin — кто двинул
  "auto": false,
  "admin_id": 0,              // кто из админов, если source=admin
  "balance_after": 125,       // сколько стало на этом счёте
  "meta": { "devices": 1 }    // подробности операции, состав зависит от kind
}
```

### Как рисовать строку

```
знак и цвет  → amount < 0 ? красный «−75 ₽» : зелёный «+100 ₽»
заголовок    → title
подпись      → description
пометка      → source = auto ? «автоматически» : admin ? «админ #{admin_id}» : ""
остаток      → balance_after
```

**Не берите знак из описания и не считайте всё положительным.** Ровно на
этом старая панель показывала «Продление подписки на 30 дней +100» —
списание выглядело как пополнение.

### Коды операций (`kind`)

| kind | Что это | Знак | Что в `meta` |
|---|---|---|---|
| `topup` | Пополнение клиентом | + | `paid` — сколько реально заплатил, `bonus`, `provider` |
| `plan` | Покупка подписки | − | `plan`, `days` |
| `renewal` | Автопродление | − | `plan`, `days` |
| `devices` | Доп. устройства: покупка и месячная плата | − | `devices`, `package_id` |
| `bypass` | Покупка трафика ByPass | − | `gb` |
| `private_server` | Личный сервер: заказ и продление | − | `plan`, `location`, `profile`, `server_id` |
| `gift` | Подарок другому человеку | − | `plan`, `to_user_id` |
| `promo` | Промокод | + | `code` |
| `referral` | Реферальный процент | + | `friend_id`, `friend_topup` |
| `campaign` | Бонус возвратной кампании | + | `campaign` |
| `survey` | Бонус за опрос | + | — |
| `payout` | Вывод: перевод на баланс или выплата по реквизитам | ± | `external` |
| `refund` | Возврат неудавшейся операции | + | зависит от операции |
| `admin` | Правка администратора | ± | — |
| `other` | Не опознано | ± | — |

`kind` проставляется в коде явно; если где-то забыли — угадывается по
описанию (`app/repositories/balance_log.py`, функция `guess_kind`). Строк
`other` в норме быть не должно: увидели — скажите, добавим код.

### Два счёта

`account: "balance"` — обычный баланс, `account: "referral"` — реферальный.
Реферальный процент падает на второй, и на первом при этом ничего не
меняется. Складывать их в одну колонку нельзя: получится «пополнение»,
которого человек на балансе не увидит.

Перевод реферального на баланс пишется **двумя** строками: минус на
реферальном и плюс на обычном. Выплата по реквизитам — одна строка, минус
на реферальном (деньги ушли на карту, до баланса бота они не доходят).

### Выручка

Не всё, что «плюс», — деньги компании:

```
выручка          = kind = topup           (meta.paid — сумма без бонуса)
расход маркетинга= kind ∈ {promo, referral, campaign, survey}
потребление      = kind ∈ {plan, renewal, devices, bypass, private_server, gift}
```

Для точной выручки лучше коллекция `payments` (раздел 6): там платёж, а не
его отражение на балансе.

## 3. Что нажимал пользователь

**Массив `logs` внутри документа пользователя**, последние 350 записей:

```jsonc
{ "action": "Действие пользователя", "details": "m:profile:",
  "timestamp": "30.08.2026 15:04:22" }
```

`details` — это код экрана или кнопки: `m:profile:`, `dev:list:`,
`/start`, `text:7`. Расшифровка — в `app/bot/middlewares/actions.py`.

Значения `action`:

| action | Что произошло |
|---|---|
| `Действие пользователя` | нажатие кнопки или команда |
| `Начисление` | деньги пришли (дублирует журнал, для быстрого взгляда) |
| `Списание` | деньги ушли |
| `Автоматическое действие` | сделал бот: автопродление, устройства, реф. начисление |

Массив обрезан до 350 записей — это защита документа от предела Mongo в
16 МБ. **Полная история денег — только в `balance_log`.**

## 4. Старые транзакции (до версии 104)

**Массив `info.transactions`**, последние 500. Три разных формата в одном
массиве — разбор описан в `docs/DB_SCHEMA.md`, раздел 2. Новый бот пишет
формат B: `{amount: ±N, dt: Date, description: "…"}`, **со знаком**.

Панели он нужен только для истории до появления журнала. Всё, что после, —
в `balance_log`, там полнее и с категориями.

`logs_balance` — коллекция **старого** бота. Новый в неё не пишет, суммы
там без знака. Годится только как архив до даты переезда.

## 5. Покупки ByPass

**Массив `info.bypass_stats.purchases`**:

```jsonc
{ "amount_gb": 3, "price": 0, "at": Date }
```

Те же покупки есть и в журнале с `kind: "bypass"` — там они со знаком и
с остатком баланса.

Поле `at` появилось в версии 104: у покупок старше даты нет вообще, это не
ошибка панели.

## 6. Платежи

**Коллекция `payments`** — то, что пришло от платёжных систем:

| Поле | Смысл |
|---|---|
| `txid` | id платежа у провайдера, уникальный |
| `user_id` | кому |
| `amount` | сколько заплачено (без бонуса) |
| `provider` | cardlink, tribute, heleket… |
| `status` | `registered` → `credited`, либо ошибка |
| `created_at` | когда |
| `payload` | сырой ответ провайдера |

Это первоисточник выручки. `balance_log` показывает, что человеку
зачислили (с бонусом), `payments` — сколько он реально заплатил.

## 7. Личные серверы

**Коллекция `private_servers`**: `_id` (`srv_xxxxxxxx`), `owner_id`,
`plan`, `location`, `profile`, `status`, `slots`, `members[]`, `price`,
`paid_until`, `next_charge_at`, `squad_uuid`.

**Коллекция `private_pool`** — машины, поднятые заранее:
`squad_uuid`, `location`, `profile`, `added_at`, `added_by`.

Деньги за них — в журнале, `kind: "private_server"`, `meta.server_id`.

## 8. Что показывать в карточке первым

Порядок по частоте вопросов в поддержку:

1. **Движение денег** — `balance_log`, свежие сверху, фильтр по `kind`
   и периоду. Это ответ на 80% обращений.
2. Подписка: до какой даты, тариф, лимит устройств.
3. ByPass: до какой даты, сколько трафика.
4. Действия — `logs`, чтобы понять, что человек нажимал перед проблемой.
5. Платежи — `payments`, когда спор про деньги.

Сверка, которая экономит время: `sum(balance_log.amount)` по
`account: "balance"` должна сходиться с `info.balance`, если журнал вёлся
с самого начала. Расхождение = операции до версии 104.
